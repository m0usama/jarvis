Now for your learning moment on agent loops: plan, act, observe.

When developers first build with large language models, they typically use a single request and response. The user asks a question, the model responds, and execution ends. An agent loop, by contrast, gives the model an iterative framework to solve complex problems through three repeated phases: planning, acting, and observing. 

In the planning phase, the model receives a goal along with a list of available tools, such as database query functions, calculators, or file system readers. The model assesses the current state, reasons about what is missing, and chooses a specific tool call. 

In the acting phase, your Python application intercepts that tool choice, executes the underlying function, and captures the result. The model does not execute code directly; your application acts on its behalf using controlled, local logic.

In the observing phase, your code appends the function's output back into the conversation history as an observation. The loop returns to the planning step, where the model inspects this fresh observation. It asks itself: is the goal met, or do I need another step? If the goal is satisfied, it outputs the final answer and exits the loop. If not, it selects the next action.

Consider a practical example in a print shop. Suppose an agent is tasked with finding out if a client's job can be fulfilled today. In step one, planning, the model decides to call a stock check function for heavy gloss paper. In step two, acting, your code runs a SQL query against the inventory database and discovers zero sheets are available. In step three, observing, your script feeds that stock result back to the model. The model enters a new loop cycle: it plans to query the supplier delivery schedule, your code acts by checking the incoming freight log, and the model observes that paper arrives at noon. Finally, the model determines it has enough context and returns a clear, complete response stating that printing can proceed this afternoon.

In production engineering, building reliable agent loops requires strict guardrails. You must enforce maximum iteration counters to prevent infinite loops, maintain token budgets, and validate tool outputs using schemas like Pydantic so the model never acts on corrupted data.
