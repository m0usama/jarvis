Now for your learning moment: Function calling, or tool use, in language model applications.

Earlier we looked at webhooks versus polling to receive external events. Function calling addresses a different problem: how a language model interacts with external code and external data. Large language models only predict text. They cannot query a live database, check an external API, or run a calculation on their own.

Function calling bridges this gap. When you make an API call to a model, you provide your prompt along with a list of tool definitions written as JSON schemas. These schemas describe the function name, its purpose, and the exact parameters it expects. If the model determines it needs external information to answer your request, it does not invent an answer. Instead, it stops generating regular text and outputs a structured JSON object containing the function name and the exact arguments needed to run it.

Your application code inspects this response, detects that a tool call was requested, parses the arguments, runs your native Python function, and gets the result. Finally, your code passes that result back to the model in a follow-up message, allowing the model to incorporate the real-world data into its final answer.

Consider a practical example from print management. A user asks your assistant, what is the print status for job card four-eight-two? The model has no access to your shop floor database. But because you defined a tool called get job status taking a job id integer, the model emits a tool call specifying job id four-eight-two. Your Python script executes a local SQL query against your job table, retrieves the record indicating it is currently in preflight, and sends that string back to the model. The model then tells the user, job card four-eight-two is currently in preflight.

In production engineering, function calling is the bedrock of dependable agent architectures. Rather than asking a model to execute business logic, you force it to emit validated schemas, keeping execution safely within your own tested, deterministic Python functions.
