Now for your learning moment: fine-tuning versus retrieval-augmented generation versus prompting.

When designing an AI system, engineers often default to the wrong approach because they confuse knowledge retrieval with behavioural alignment. Understanding the boundary between prompt engineering, retrieval-augmented generation or RAG, and fine-tuning prevents wasted compute, slow iteration cycles, and fragile architectures.

Prompt engineering is zero-shot or few-shot instruction. You modify the system instructions, provide formatting constraints, and inject a handful of input-output examples directly into the model context window. It requires no additional infrastructure, changes instantly, and costs nothing in training compute. However, it is strictly limited by the context window and can struggle with massive knowledge bases or complex stylistic patterns.

Retrieval-augmented generation brings external, dynamic knowledge into that prompt. Instead of relying on what the model memorised during pre-training, you query an external database, such as an analytical data store or document search index, retrieve relevant context, and feed it into the prompt at runtime. RAG is ideal when data updates frequently, when answers require strict source attribution, or when users need access control over proprietary business records.

Fine-tuning changes the model weights themselves. You take an existing base model and train it on hundreds or thousands of paired examples to adapt its style, tone, structured output formatting, or domain-specific grammar. Fine-tuning does not reliably teach a model new facts. If you fine-tune to inject facts, the model will still hallucinate when queried slightly differently, and retraining every time information changes is impractical. Fine-tuning teaches how to behave, speak, or structure syntax; RAG teaches what to know.

In real engineering work, you choose prompting first to test feasibility. If the task requires private, rapidly changing business data, like querying a print catalogue, checking stock levels, or cross-referencing trade customer histories, you implement RAG. If you need a smaller open model to deterministically output complex domain files without verbose system prompts, such as compiling bespoke InDesign markup or strict internal domain DSLs, you use fine-tuning to bake that syntax into the weights. A mature system often combines them: a fine-tuned model optimized for structured execution, guided by runtime context fetched through RAG.
