Now for your learning moment: structured outputs and JSON schema validation with Pydantic.

You previously learned how function calling uses tool definitions to interact with external code. Structured outputs take this a step further by forcing a model to return data that conforms precisely to a strict schema, eliminating unpredictable strings and messy markdown parsing.

Pydantic is the primary Python library used for this. You define a Python class that inherits from Pydantic's BaseModel, declaring each field along with its type, such as strings, integers, or lists. Under the hood, this generates a strict JSON schema that is supplied to the model's response configuration. The model engine constrains its token generation so it physically cannot emit tokens that violate that schema.

For example, imagine you are extracting job ticket data from your print shop photo workflow. You create a Pydantic class called JobCard with fields for customer name as a string, quantity as an integer, and finished size as a string. Instead of prompting the vision model to return raw text and hoping it writes clean JSON, you pass that Pydantic schema directly into the API call. The model returns valid JSON guaranteed to map back into your Python object.

In production engineering, this is indispensable. If a model tries to output a missing field or passes text into an integer field, validation raises an immediate error before the bad data touches your database or Google Sheets. It turns non-deterministic language generation into reliable, typed contracts that integrate seamlessly with FastAPI and downstream data pipelines.
