Now for today's learning moment: secrets management and API key hygiene.

In development, your code needs credentials to talk to external tools, such as API keys for OpenAI, database passwords, or webhook secret tokens. Secrets management means keeping these credentials completely separate from your source code so they are never hardcoded, never exposed in client scripts, and never committed to a git repository.

Here is a concrete example. Imagine you write a FastAPI service or a Python workflow script that calls a model endpoint. Instead of placing the raw key string inside your Python file, you store it in a local environment file named dot env. Inside your Python script, you use a library like python-dotenv or Pydantic Settings to load the key into memory at runtime using environment variables. Crucially, your git ignore file lists the dot env file so git skips it entirely, while a sample template file named dot env dot example is committed to show team members which variable names are required without revealing the real credentials.

In professional software engineering, exposing an API key in a public repo can result in immediate credential compromise, thousands of pounds in unauthorized usage, and data breaches. Production systems store secrets in specialized vaults like AWS Secrets Manager or GitHub Actions Repository Secrets, injecting them securely into running containers at startup. Demonstrating immaculate secret hygiene in your public portfolio proves to engineering managers that you can be trusted with sensitive corporate infrastructure on day one.
