Learning Moment: SQL Indexing and Query Plans

  • Relational queries without an index perform sequential scans across all disk rows, leading to heavy I/O and high latency as tables scale.
  • An index maintains a secondary balanced tree structure mapping column values to physical storage addresses, enabling logarithmic lookup times.
  • Indexes introduce a trade-off: they accelerate reads but add write overhead, as inserts, updates, and deletes must update the index structure.
  • Engineers inspect execution plans using `EXPLAIN QUERY PLAN` (often with an analyze flag) to examine estimated costs and verify whether a query uses an index scan or falls back to a sequential scan.
  • Example: In an orders table with 500,000 rows, querying `WHERE customer_id = 42` scans every row sequentially; creating an index on `customer_id` builds a tree that allows the database engine to locate the matching keys in a few milliseconds.
