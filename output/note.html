Learning Moment: Retries, Backoff, and Idempotency in Automations

  • Network hiccups and rate limits cause transient failures when scripts communicate with external systems.
  • Immediate retries can cause a thundering herd problem that overwhelms struggling servers.
  • Exponential backoff with jitter avoids synchronized traffic spikes by increasing delays (e.g., 1s, 2s, 4s) plus a small random delay.
  • Retrying safely requires idempotency, ensuring operations produce the exact same outcome whether run once or multiple times.
  • Non-idempotent actions (like charging payments or inserting orders) require unique idempotency keys to safely return previous results without executing side effects twice.
  • Example: Attaching a unique idempotency key (such as a hash of job card details or a timestamped UUID) to a request so the receiving system checks if it already handled it and returns the original success message without duplicating the action.
