Learning Moment: Star Schemas and dbt

  • Transactional databases normalize operational data across fragmented tables for fast single-row writes, but result in slow, complex analytical queries.
  • Star schemas reorganize data into a central fact table (containing quantitative numerical metrics and foreign keys) surrounded by dimension tables (containing descriptive context).
  • dbt (data build tool) replaces brittle extraction scripts with declarative version-controlled SQL `SELECT` statements to transform raw tables into staging and dimensional models.
  • dbt automatically infers dependency graphs, tests primary keys, and builds reliable, audit-ready data models for downstream automations.
  • Example: In a print business, a central `fact_print_jobs` table stores sheet counts, print duration, and revenue, linking to `dim_customer`, `dim_machine`, and `dim_date`; calculating total sheets by customer tier requires only one fast join instead of querying multiple normalized tables.
